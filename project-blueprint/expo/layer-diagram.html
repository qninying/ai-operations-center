Why the recommendation can't write back to production on its own

Seven layers, but the argument isn't the count — it's the one arrow that doesn't exist: nothing routes from a model's output straight back to the data it read. It has to pass through a human first, and every hop along the way carries the same correlation ID.

The one arrow that isn't there

There's no line from 04 · Reasoning or 03 · Orchestration straight down to 06 · Data & Infrastructure. That's deliberate, not an omission — a model's output is a recommendation until a real, password-verified human at the Application layer approves it. Remove the dashed line and the diagram still makes sense; remove Governance and it stops being a governed system at all.

Why the correlation ID is drawn as its own layer

Audit isn't bolted onto Governance — it's independent of every layer, which is exactly why it can catch a layer lying to another one. In practice this was a real bug: the monitoring path and the HTTP-request path in CoreOps originally minted two different IDs for the same incident, so the "one ID, every hop" line in this diagram wasn't true until it was fixed.
