02 · Before and after · 60s

Eight steps became three.

Before Diagnosing a real incident

  1. Notice something's wrong (if anyone does)
  2. SSH into the affected system
  3. Manually query logs / DMVs / pg_stat_activity
  4. Form a hypothesis about root cause
  5. Decide the safe fix, by hand
  6. Execute the fix
  7. Manually re-check whether it worked
  8. Write up what happened (if anyone bothers)

After Same task, CoreOps

  1. Incident auto-detected, shown on the dashboard
  2. Troubleshoot: evidence-cited root cause from a real Claude call
  3. Approve: the one human action required

Text equivalent: a two-column list comparing the same task, diagnosing a real incident, before and after CoreOps. Five steps are struck through (removed): SSH access, manual log/DMV queries, manual fix decisions, manual re-checking, manual write-up. One step is marked new: an AI-generated, evidence-cited root cause (Troubleshoot).
